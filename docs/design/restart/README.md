## What impl takes from here

- One route. The wizard steps are gone; every edit rates the picked design at once, and the ranking re-ranks in its own worker (ADR: rating never waits behind sizing). A phone shows the same docks as sheets, with no second layout to maintain.
- Tokens: `tokens.css` keeps the website scale and adds the cockpit's own tokens: `--dock` (translucent dock with backdrop blur), `--dock-rule`, `--canvas-1` and `--canvas-2` (the stage gradient), `--model-face`, `--model-metal` and `--model-fill` (shaded parts), `--dim` (dimension lines), `--mono` (every number), and the flow and warn/bad colours.
- Model: `model.js` builds every part from the engine's geometry (shapes.md section 3), and the same build serves both modes. In 3D, the shaded faces go to one canvas. Edges, flows and dimensions go to a second canvas over depth-only occluders, and a blurred copy beneath gives the glow (dark only). In GA, one orthographic camera per view renders the line build in its own viewport, with a shared clip plane for the section. Dimensions are world-space lines with HTML labels in mono, one layer per view.
- Numbers come from the recorded `select` step in `validation/regression-baseline.json`, the same as last round. Flow reads 725 m³/h, which is 200 kg/s at 993.4 kg/m³. The fan curve's shape is drawn for layout only.
- `./render.sh` renders every state with Playwright's cached headless Chromium (WebGL by SwiftShader). It loads three.js from `web/vendor/`.
